# V1.5 — Optional AI Script Provider

V1.5 builds on V1.4 in a separate branch and preserves the existing function signature used by the dashboard and daily runner.

## What's new
- Adds an optional OpenAI-compatible chat-completions provider using Python standard-library HTTP tools; no additional package is required.
- If AI_API_BASE_URL, AI_API_KEY, and AI_MODEL are all configured, script generation attempts to use that provider.
- If no provider is configured, it uses the existing local template. If the provider errors, the default behavior also falls back to the local template so the daily workflow can continue.
- Set AI_REQUIRE_REMOTE=1 if you prefer a provider error to stop generation instead of fallback.
- AI provider output is length-checked (70-145 words). This is a format check, not fact-checking.
- The topic selector still draws from the curated local topic bank; this version does not browse sources, verify facts, or guarantee novelty.


## Optional AI configuration
- Leave AI_API_BASE_URL, AI_API_KEY, AI_MODEL unset to use the local template at no API cost.
- If you have an API provider that supports OpenAI-compatible chat completions, set all three values in your local environment. Example base URL format: https://provider.example/v1 (replace with the actual provider endpoint). Do not use this example literally.
- Keep API keys private. Do not commit real keys into GitHub or send them in chat.
- Check the provider's price, free-tier limits, data handling, and model availability before use. The code cannot promise that any external provider is free.
- Test script generation in the dashboard and manually review the narration before enabling unattended uploads.
